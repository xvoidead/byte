**Рекурсия** — это когда метод вызывает сам себя. Звучит странно, но многие задачи так решаются проще всего: большая задача сводится к такой же, но поменьше.

## Базовый случай и шаг рекурсии

Факториал: n! = n · (n − 1)!, а 0! = 1.

```java
static long factorial(int n) {
    if (n == 0) {
        return 1;                    // базовый случай — ответ известен сразу
    }
    return n * factorial(n - 1);     // шаг — задача сводится к меньшей
}
```

У любой рекурсии должны быть две части:

1. **базовый случай** — когда ответ известен без новых вызовов;
2. **шаг** — вызов для задачи поменьше, который рано или поздно приведёт к базовому случаю.


## Как это выполняется

Каждый вызов метода ждёт результата следующего. Java хранит эти незавершённые вызовы в **стеке вызовов**:

```
factorial(3)
  └ 3 * factorial(2)
          └ 2 * factorial(1)
                  └ 1 * factorial(0) = 1
                  = 1
          = 2
  = 6
```

Если забыть базовый случай, вызовы никогда не закончатся, стек переполнится и программа упадёт с ошибкой `StackOverflowError`.

```quiz

+ Программа упадёт с ошибкой StackOverflowError

> Вызовы будут вкладываться друг в друга бесконечно, пока не закончится память стека вызовов.
```

## Рекурсия вместо цикла

Сумму цифр числа можно посчитать и без цикла:

```java
static int digitSum(int n) {
    if (n < 10) {
        return n;
    }
    return n % 10 + digitSum(n / 10);
}
```

Любую рекурсию можно переписать циклом и наоборот. Выбирают то, что понятнее для конкретной задачи.

## Когда рекурсия незаменима

Рекурсия естественна там, где задача разбивается на похожие подзадачи: обход папок на диске, разбор математических выражений, игры и головоломки.

Классический пример — **Ханойские башни**. Есть три стержня A, B и C. На A надеты диски разного размера: снизу большой, сверху маленький. Нужно перенести всю башню на C, соблюдая правила:

- за ход переносится один верхний диск;
- нельзя класть больший диск на меньший.

Задача, которая кажется сложной, решается в три мысли. Чтобы перенести `n` дисков с A на C через B:

1. перенести `n − 1` дисков с A на B (через C) — это та же задача, только меньше;
2. перенести самый большой диск с A на C;
3. перенести `n − 1` дисков с B на C (через A).

А один диск просто переносится одним ходом — это базовый случай.

## Когда рекурсия опасна

Наивная рекурсия для чисел Фибоначчи, `fib(n) = fib(n - 1) + fib(n - 2)`, вычисляет одно и то же много раз. Уже `fib(50)` будет считаться очень долго. Такие задачи лучше решать циклом или запоминать уже посчитанные значения.
