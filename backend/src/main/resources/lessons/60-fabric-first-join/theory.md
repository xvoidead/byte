Игровые события часто помогают хранить небольшое состояние мода. Например, множество может помнить, кто уже подключался.

## Подписываемся на JOIN

Зарегистрируйте `ServerPlayConnectionEvents.JOIN` в `onInitialize()`. Callback получает handler, отправителя пакета и сервер; игрок доступен через `handler.player`.

```java
ServerPlayConnectionEvents.JOIN.register((handler, sender, server) -> {
    String name = handler.player.getName().getString();
});
```

Не регистрируйте callback внутри события входа: иначе при каждом подключении появится ещё один обработчик.

```quiz
? Где один раз регистрируют JOIN callback?
- Внутри цикла входа
+ В onInitialize()
- В файле config/byte.json
> Entry point вызывается при загрузке мода.
```

## Запоминаем имя

Создайте `Set<String>`. `add` вернёт `true`, если имя появилось впервые, и `false`, если оно уже было. Используйте `toLowerCase(Locale.ROOT)`, чтобы `Steve` и `steve` считались одним игроком.

```quiz
? Что означает true от seen.add(key)?
+ Имя добавлено впервые
- Игрок отключился
- Множество очищено
> Set.add сообщает, изменилось ли множество.
```

## Разные сообщения

Получите имя через `handler.player.getName().getString()`, но храните отдельный нормализованный ключ. Отправить сообщение можно через `Text.literal(...)` и `sendMessage(..., false)`.

Состояние хранится только в памяти этого экземпляра мода; перезапуск сервера его сбросит. Для постоянных данных понадобится файл или база данных.

```quiz
? Зачем имя приводят к нижнему регистру перед добавлением в Set?
- Чтобы убрать пробелы из чата
+ Чтобы не различать Steve и steve
- Чтобы узнать UUID
> Нормализация делает ключ сравнения единообразным.
```
