Minecraft обновляет мир небольшими шагами — **тиками**. При обычной скорости 20 TPS (ticks per second) за секунду происходит около 20 таких шагов. Fabric API предоставляет callback-и на разных этапах серверного тика.

## Регистрируем tick callback

`ServerTickEvents.END_SERVER_TICK` вызывается в конце каждого серверного тика. Его регистрируют в `ModInitializer`:

```java
ServerTickEvents.END_SERVER_TICK.register(server -> {
    // Этот код вызывается около 20 раз в секунду.
});
```

Callback получает `MinecraftServer`. В нём можно получить игроков через `server.getPlayerManager().getPlayerList()` и отправить им `Text.literal(...)`.

```quiz
? Сколько раз в секунду обычно срабатывает END_SERVER_TICK?
- 1
+ Около 20
- 1000
> Minecraft обычно стремится поддерживать 20 ticks per second.
```

## Считаем тики

Чтобы выполнять действие реже, храните счётчик как поле мода, а не создавайте его внутри callback-а. Локальная переменная внутри callback-а заново создавалась бы при каждом вызове.

```java
private int ticks;

private void onTick(MinecraftServer server) {
    ticks++;
    if (ticks % 20 == 0) {
        server.getPlayerManager().getPlayerList().forEach(player ->
                player.sendMessage(Text.literal("Прошла секунда."), false));
    }
}
```

`%` — остаток от деления. Если `ticks % 20` равен нулю, число делится на 20 без остатка. Тестовый сервер Byte позволяет продвигать тики вручную.

```quiz
? На каком тике ticks % 20 впервые станет равен нулю?
- 19
+ 20
- 21
> 20 делится на 20 без остатка; 19 — нет.
```

## Не блокируем игровой поток

Никогда не ждите время через `Thread.sleep()` внутри игрового callback-а. Пока поток спит, сервер не обрабатывает игроков и мир; вместо этого используйте тики. Для длительной или дорогой работы изучите фоновые задачи, но безопасный доступ к миру всё равно должен происходить на серверном потоке.

`END_SERVER_TICK` — серверное событие. Клиентский код подключается отдельно через `ClientModInitializer` и клиентские события, которые разберём в конце трека.

```quiz
? Почему Thread.sleep(1000) внутри tick callback — плохая идея?
- Он ускоряет сервер
- Он запускает лишние тики
+ Он блокирует поток, который обслуживает игровой сервер
> Tick callback должен быстро завершаться; таймер строят на счётчике тиков, а не на ожидании.
```
