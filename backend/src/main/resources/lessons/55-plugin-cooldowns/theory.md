## Состояние для каждого игрока

Создайте `Set<UUID>` активных cooldown. `UUID` не меняется при переименовании игрока, поэтому он надёжнее отображаемого имени. `Set.add` сразу сообщает, был ли игрок уже в множестве: `false` означает, что cooldown активен.

```quiz
? Что означает false от coolingDown.add(id)?
- Игрок получил разрешение
+ Этот UUID уже в множестве
- Множество очистилось
> add возвращает false, если элемент уже встречался.
```

## Снимаем cooldown по тикам

Запланируйте удаление UUID через `BukkitRunnable.runTaskLater(this, 5L)`. Задача выполняется через пять серверных тиков; она не должна удерживать или блокировать игровой поток.

```java
new BukkitRunnable() {
    @Override public void run() { coolingDown.remove(id); }
}.runTaskLater(this, 5L);
```

```quiz
? В чём измеряется delay у runTaskLater?
- В минутах
+ В серверных тиках
- В количестве игроков
> Аргумент delay задаётся в тиках.
```

## Не блокируем команду

Не используйте `Thread.sleep`: он остановит поток игрового сервера. Если отправитель — не игрок, сообщите об этом и выйдите. Список UUID позволяет игрокам использовать команду независимо друг от друга.

```quiz
? Почему cooldown хранится по UUID?
- Чтобы запретить команду всем сразу
+ Чтобы ограничение одного игрока не мешало другим
- Потому что Set принимает только UUID
> Ключом состояния служит конкретный игрок.
```
