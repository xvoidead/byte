Соберём знания из предыдущих уроков в небольшой Bukkit-плагин: события блоков, команды, YAML-конфиг и коллекции. Экономика будет учебной и храниться только в памяти — постоянное хранение можно добавить позже.

## Храним балансы

Для связи имени игрока с числом монет подойдёт `Map<String, Integer>`. При входе создайте запись только если её ещё нет:

```java
private final Map<String, Integer> balances = new HashMap<>();

@EventHandler
public void onJoin(PlayerJoinEvent event) {
    balances.putIfAbsent(event.getPlayer().getName(), 0);
}
```

`putIfAbsent` не перезапишет существующий баланс нулём. Сумму за блок можно получить из конфига по имени материала: например, `rewards.STONE`.

```quiz
? Что останется в Map после putIfAbsent("Steve", 0), если там уже лежит баланс 12?
- 0
+ 12
- null
> putIfAbsent добавляет значение только при отсутствии ключа и не затирает старый баланс.
```

## Начисляем награду

Событие `BlockBreakEvent` даёт тип блока. `getConfig().getInt(path, 0)` вернёт ноль, если награда для этого материала не настроена. `Map.merge` удобно увеличивает текущий баланс:

```java
int reward = getConfig().getInt("rewards." + block.getType().name(), 0);
if (reward > 0) {
    balances.merge(player.getName(), reward, Integer::sum);
}
```

Не начисляйте награду, если событие отменено другим плагином; в расширенной версии проверьте `event.isCancelled()`.

```quiz
? У Steve 7 монет, а за блок начислено 3. Что сделает balances.merge("Steve", 3, Integer::sum)?
- Удалит запись
+ Сохранит 10
- Создаст вторую запись с тем же ключом
> Функция Integer::sum объединяет старое и новое значения для одного ключа.
```

## Переводы и таблица лидеров

Перед переводом выполните все проверки: адресат в сети, сумма положительная и денег хватает. Только после этого изменяйте оба баланса — иначе неудачная команда может потерять монеты.

Топ игроков можно получить из `getOnlinePlayers()` и отсортировать компаратором: сначала баланс по убыванию, затем имя по возрастанию. При равных балансах такой порядок будет стабильным и понятным.

```java
players.sort(Comparator
        .comparingInt((Player p) -> balances.getOrDefault(p.getName(), 0)).reversed()
        .thenComparing(Player::getName));
```

Не забывайте включать игрока с нулевым балансом и ограничивать вывод, например, пятью строками.

```quiz
? Какой баланс должен быть у получателя после перевода 4 монет, если до этого было 6?
- 2
+ 10
- 24
> Получатель получает сумму перевода: 6 + 4 = 10. Сначала убедитесь, что у отправителя хватает средств.
```
