Калькулятор, который понимает `2 + 3 * (4 - 1)`, — классическая задача, на которой учатся писать разборщики языков. Этим же способом устроены компиляторы, в том числе javac.

## Что будем делать

Программа получает строку-выражение и считает его с учётом приоритета: сначала скобки, потом умножение и деление, потом сложение и вычитание. Числа целые, деление — целочисленное.

```
2 + 3 * 4        → 14
(2 + 3) * 4      → 20
-(4 - 6) * 3     → 6
```

## Токены

Сначала строку удобно разбить на **токены** — неделимые кусочки: числа, знаки операций и скобки. Пробелы между ними не важны.

```
"12*(3 + 4)"  →  12   *   (   3   +   4   )
```

Можно обойтись и без отдельного списка токенов: читать строку посимвольно, пропуская пробелы. Так и сделаем — будем хранить позицию `pos` и смотреть на текущий символ.

## Грамматика

Приоритет операций удобно описать правилами — **грамматикой**:

```
выражение  = слагаемое { ("+" | "-") слагаемое }
слагаемое  = множитель { ("*" | "/") множитель }
множитель  = число | "(" выражение ")" | "-" множитель
```

Фигурные скобки означают «повторить сколько угодно раз». Правила вкладываются друг в друга: выражение состоит из слагаемых, слагаемое — из множителей, а множитель может снова содержать целое выражение в скобках.

```quiz
? В каком порядке вычислится `8 - 2 - 1` по этой грамматике?
+ (8 - 2) - 1 = 5
- 8 - (2 - 1) = 7
- Порядок не определён
- Сначала 2 - 1, потому что вычитание справа
> Цикл в правиле «выражение» обрабатывает слагаемые слева направо, накапливая результат: сначала 8 − 2, потом − 1.
```

## Рекурсивный спуск

Каждое правило грамматики превращается в метод:

```java
long parseExpression() {
    long value = parseTerm();
    while (peek() == '+' || peek() == '-') {
        char op = next();
        long right = parseTerm();
        value = op == '+' ? value + right : value - right;
    }
    return value;
}
```

`parseTerm` устроен так же, но с `*` и `/` и вызывает `parseFactor`. А `parseFactor` разбирает число, минус или скобки — и для скобок снова вызывает `parseExpression`. Методы вызывают друг друга по кругу — это тоже рекурсия, только косвенная. Отсюда и название — **рекурсивный спуск**.

## Ошибки

Выражение может быть некорректным: `2 +`, `(1`, `2 3`, `*5`. Удобно бросать своё исключение из любого места разбора и ловить его один раз снаружи:

```java
class CalcException extends RuntimeException {
    CalcException(String message) {
        super(message);
    }
}
```

Важная деталь: после разбора всего выражения нужно проверить, что строка закончилась. Иначе `2 3` посчиталось бы как `2`, а остаток молча пропал бы.

```quiz
? Как поступить с выражением `2 3`?
- Вернуть 2 — первое число разобрано
- Вернуть 5 — сложить числа
+ Сообщить об ошибке: после выражения остался лишний текст
- Вернуть 23 — склеить цифры
> Разбор должен съесть строку целиком. Если после выражения что-то осталось, выражение некорректно.
```

## Деление на ноль

При делении проверьте делитель и бросьте исключение с понятным текстом. Так пользователь увидит «деление на ноль», а не падение программы.
