# byte

Сайт, на котором можно изучать Java с работающей IDE прямо в браузере: короткие уроки с вопросами, редактор уровня VS Code, настоящий компилятор, интерактивная консоль и задания с автоматической проверкой.

## Возможности

- **53 урока в 12 модулях** — от первой программы до Stream API, баз данных, серверных плагинов Bukkit/Paper и модов Fabric; также три проекта (игра «Угадай число», калькулятор выражений и менеджер задач) и трек конфигов.
- **Урок по шагам**: теория разбита на короткие шаги, между ними — вопросы «что выведет программа?» с разбором ответа. Ссылку можно дать на конкретный шаг (`?step=3`), листать можно стрелками.
- **Задание с автопроверкой**: открытые примеры, скрытые тесты и **случайные тесты**, которые меняются при каждой проверке, — заучить ответы не получится.
- **Защита от подгона**: требования к решению («используйте цикл», «напишите метод», «не пишите готовые числа») проверяются по синтаксическому дереву программы.
- **Подсказки и разбор**: подсказки открываются по одной; эталонное решение — после прохождения или после всех подсказок и нескольких попыток.
- **Редактор Monaco** (тот же, что в VS Code): подсветка Java, автодополнение классов с автоматическим `import` и методов после точки (`in.`, `list.stream().`), сниппеты в стиле IntelliJ (`sout`, `psvm`, `fori`, `foreach`…), `Ctrl+Enter` — запуск, `Ctrl+Shift+Enter` — проверка.
- **Ошибки во время набора**: код компилируется в фоне, ошибки подчёркиваются сразу, с пояснениями на русском.
- **Интерактивная консоль**: программа ждёт ввода с клавиатуры, как в настоящем терминале; зависшую программу можно остановить.
- **Проекты из нескольких файлов**: вкладки как в IDE — классы в отдельных файлах, `config.yml`, `data.json`, ресурсы в `resources/`. Программа читает и пишет файлы в своей папке, а созданные ею файлы появляются во вкладках.
- **Библиотеки и Minecraft API**: Gson и SnakeYAML для конфигов; Paper API + MockBukkit для сценариев Bukkit-плагинов; уроки Fabric используют учебную симуляцию нужных callbacks — она проверяет логику, но не запускает Minecraft и не собирает полноценный mod JAR.
- **Настоящая Java 21** в изолированной песочнице.
- **Прогресс и черновики** сохраняются в браузере, регистрация не нужна.
- **Анонимная статистика** для автора курса: где ученики застревают, какие вопросы самые трудные, какие ошибки делают чаще всего.
- Адаптивная вёрстка, анимации с учётом `prefers-reduced-motion`, всё (шрифты, редактор) загружается со своего сервера.

## Архитектура

```
frontend/  React 19 + TypeScript + Vite + Monaco Editor
backend/   Spring Boot 4 + Java 21, встроенная H2 для статистики
e2e/       сквозные тесты на Playwright
```

**Бэкенд** (`backend/src/main/java/dev/byteide`):

| Пакет | Что делает |
|-------|------------|
| `runner` | `JavaCompilationService` компилирует код встроенным `javac` и выдаёт диагностику во время набора; `Sandbox` и `ProcessExecutionService` запускают программу в отдельной JVM с ограничениями; `CodeRunner` управляет очередями запусков. |
| `sandbox` | `SandboxLauncher` — точка входа дочерней JVM: загружает класс ученика и включает менеджер безопасности. |
| `console` | WebSocket `/api/console` для интерактивной консоли. |
| `lessons` | Загрузка уроков, разбор шагов и вопросов, генерация случайных тестов, проверка требований (`CodeInspector`) и решений (`SolutionChecker`). |
| `analytics` | Приём анонимных событий, сводка для `/stats`, удаление старых данных. |
| `web` | REST API, ограничение частоты запросов, заголовки безопасности. |
| `site` | Отдача SPA с мета-тегами для каждой страницы, `robots.txt`, `sitemap.xml`, 404. |

Мосты из `backend/src/bridge/java` попадают только в classpath пользовательских программ: они подключают MockBukkit и базы данных к безопасным in-memory runtime. Для Fabric используется небольшая детерминированная совместимая прослойка только для изучаемых entrypoint и событий; это не сервер и не клиент Minecraft.

**API**

| Метод | Путь | Описание |
|-------|------|----------|
| `GET` | `/api/lessons` | Список уроков |
| `GET` | `/api/lessons/{slug}` | Урок: шаги, задание, стартовый код, примеры, подсказки, требования |
| `POST` | `/api/lessons/{slug}/check` | `{ "files" }` → результаты тестов (вывод и файлы) и требований |
| `GET` | `/api/lessons/{slug}/solution` | Эталонное решение |
| `POST` | `/api/run` | `{ "files": [{ "name", "content" }], "stdin" }` → вывод, диагностика и файлы рабочей папки после запуска (без интерактивности); вместо `files` можно прислать один `code` |
| `POST` | `/api/compile` | `{ "files" }` → ошибки компиляции с именами файлов для подсветки во время набора |
| `WS` | `/api/console` | Интерактивный запуск: `run` (с `files`), `input`, `eof`, `stop` → `started`, `out`, `exit` (с файлами после запуска), `compile_error`, `error` |
| `POST` | `/api/events` | Анонимные события статистики (до 50 за раз) |
| `GET` | `/api/admin/stats` | Сводка статистики, заголовок `Authorization: Bearer <BYTE_ADMIN_TOKEN>` |
| `GET` | `/api/health` | Состояние сервера и песочницы |

## Запуск для разработки

Нужны **JDK 21** (именно JDK и именно 21 — см. «Безопасность»), Maven 3.9+ и Node.js 22+.

```bash
# Терминал 1 — бэкенд на :8080
cd backend
mvn spring-boot:run

# Терминал 2 — фронтенд на :5173 (запросы /api и WebSocket проксируются на :8080)
cd frontend
npm install
npm run dev
```

Откройте http://localhost:5173. Чтобы посмотреть статистику локально, запустите бэкенд с `BYTE_ADMIN_TOKEN=любой-токен` и откройте `/stats`.

## Тесты

```bash
cd backend && mvn test          # песочница, API, лимиты, консоль, статистика и все уроки
cd frontend && npm run build    # проверка типов + сборка

# Сквозные тесты используют готовые сборки фронтенда и сервера
cd backend && mvn -DskipTests package
cd e2e && npm install && npx playwright install chromium && npx playwright test
```

`LessonsContentTest` проверяет каждый урок: эталонное решение проходит все тесты, требования и случайные тесты; стартовый код компилируется, но не проходит; ответ каждого вопроса «что выведет программа?» совпадает с настоящим выводом.

Сквозные тесты (`e2e/`) сами запускают собранный сервер на порту 8090 и проверяют в Chromium главную, прохождение урока с защитой от подгона, интерактивную консоль, песочницу, статистику и вёрстку на телефоне. Чтобы прогнать их против уже работающего сайта: `E2E_BASE_URL=https://… E2E_ADMIN_TOKEN=… npx playwright test`.

## Публикация

```bash
docker build -t byte .

# Токен для страницы /stats: придумайте сами или сгенерируйте и сохраните в менеджере паролей
BYTE_ADMIN_TOKEN=$(openssl rand -hex 24)
echo "Токен статистики: $BYTE_ADMIN_TOKEN"

docker run -d --name byte -p 8080:8080 \
  -v byte-data:/app/data \
  -e BYTE_BASE_URL=https://example.com \
  -e BYTE_CONTACT_EMAIL=hello@example.com \
  -e BYTE_ADMIN_TOKEN="$BYTE_ADMIN_TOKEN" \
  -e SERVER_FORWARD_HEADERS_STRATEGY=native \
  byte
```

Сервер нигде не показывает токен — это пароль, который вы задаёте сами. Если забыли его, посмотрите в контейнере: `docker exec byte printenv BYTE_ADMIN_TOKEN`; чтобы сменить, перезапустите контейнер с новым значением.

Образ собирает фронтенд, кладёт его в статику Spring Boot и запускает всё одним процессом от непривилегированного пользователя. Перед сервером поставьте обратный прокси с HTTPS (Caddy, nginx) — и не забудьте, что он должен пропускать WebSocket на `/api/console`.

**Ресурсы.** Каждый запуск программы — отдельная JVM (до 128 МБ кучи). По умолчанию одновременно выполняется до 4 обычных запусков и 8 интерактивных сессий, сервер занимает до 512 МБ. Комфортно — 2 vCPU и 4 ГБ RAM. На 2 ГБ уменьшите `BYTE_RUNNER_MAXCONCURRENTRUNS=2` и `BYTE_RUNNER_MAXINTERACTIVESESSIONS=4`.

### Переменные окружения

| Переменная | Зачем |
|------------|-------|
| `BYTE_BASE_URL` | Адрес сайта, например `https://byte.dev`. Нужен для канонических ссылок, Open Graph и `sitemap.xml`. |
| `BYTE_CONTACT_EMAIL` | Почта для связи на страницах «Конфиденциальность» и «Правила». |
| `BYTE_ADMIN_TOKEN` | Токен страницы `/stats`. Пока не задан, статистика недоступна (404), но события собираются. |
| `BYTE_ANALYTICS_DB` | Где хранить статистику: `mem:analytics` (по умолчанию вне Docker, пропадает при перезапуске) или файл, например `file:/app/data/analytics` (по умолчанию в образе). |
| `SERVER_FORWARD_HEADERS_STRATEGY` | `native` за обратным прокси — чтобы лимиты запросов считались по реальному IP клиента, а не прокси. |
| `PORT` | Порт сервера, по умолчанию 8080. |
| `JAVA_OPTS` | Параметры JVM сервера (в образе `-Xmx512m`). |

### Остальные настройки

В `application.yml`; любую можно переопределить переменной окружения (`byte.runner.max-concurrent-runs` → `BYTE_RUNNER_MAXCONCURRENTRUNS`).

| Параметр | По умолчанию | |
|----------|--------------|--|
| `byte.runner.timeout` | `5s` | Лимит времени обычного запуска, включая старт JVM |
| `byte.runner.cpu-limit` | `5s` | Лимит процессорного времени программы |
| `byte.runner.interactive-timeout` | `2m` | Сколько живёт интерактивная сессия |
| `byte.runner.max-memory-mb` | `128` | Куча дочерней JVM |
| `byte.runner.max-threads` | `32` | Потоков в программе ученика |
| `byte.runner.max-output-chars` | `65536` | Максимум вывода, после чего программа останавливается |
| `byte.runner.max-concurrent-runs` | `4` | Одновременных запусков и проверок; остальные ждут в очереди |
| `byte.runner.max-interactive-sessions` | `8` | Одновременных интерактивных сессий |
| `byte.runner.max-file-size-kb` | `2048` | Размер одного файла, который может записать программа (ограничение ОС) |
| `byte.runner.max-work-dir-size-kb` | `4096` | Сколько всего данных может лежать в рабочей папке программы |
| `byte.runner.max-work-dir-entries` | `100` | Сколько файлов и папок может быть в рабочей папке |
| `byte.limits.runs-per-minute` | `30` | Запусков и проверок в минуту с одного IP |
| `byte.limits.concurrent-runs-per-ip` | `2` | Одновременных программ с одного IP |
| `byte.analytics.retention-days` | `180` | Сколько дней хранить события статистики |

## Как добавить урок

1. Создайте каталог `backend/src/main/resources/lessons/NN-slug/` (номер задаёт порядок, `slug` — адрес урока).
2. Добавьте файлы:
   - `lesson.json` — модуль, название, описание, тесты, подсказки, требования и шаблон случайных тестов:
     ```json
     {
       "module": "Первые шаги",
       "title": "Название",
       "summary": "Одна строка для списка уроков.",
       "activeFile": "Main.java",
       "tests": [
         { "name": "Пример", "stdin": "2 3\n", "expectedOutput": "5\n", "hidden": false }
       ],
       "hints": ["Первая подсказка — намёк.", "Последняя — почти решение."],
       "requirements": [
         { "type": "loop", "message": "Используйте цикл." },
         { "type": "forbidLiteral", "values": ["120"], "message": "Не пишите готовый ответ." }
       ],
       "random": { "count": 3, "input": "{n=int:1..8}\n{ints:n:-50..50}\n" }
     }
     ```
   - `theory.md` — теория; каждый заголовок `##` начинает новый шаг. Вопросы пишутся блоком:
     ````
     ```quiz
     ? Что выведет программа?
         System.out.println(7 / 2);
     - 3.5
     + 3
     > Деление целых чисел отбрасывает дробную часть.
     ```
     ````
     Строки с отступом — код, `+` — правильный вариант, `-` — неправильный, `>` — объяснение.
   - `task.md` — условие задания;
   - `Main.java` — стартовый код;
   - `solution.java` — эталонное решение: по нему считается ожидаемый вывод случайных тестов, его же видит ученик в разборе.
3. Запустите `mvn test` — `LessonsContentTest` проверит урок целиком.

**Урок-проект из нескольких файлов.** Вместо `Main.java` и `solution.java` положите каталоги `starter/` и `solution/` с файлами проекта:

```
NN-slug/
  starter/Main.java  starter/Config.java  starter/resources/config.yml
  solution/Main.java solution/Config.java solution/resources/config.yml
```

Файлы `*.java` компилируются вместе, `resources/…` попадают в classpath (читаются через `getResourceAsStream`), остальные (`config.yml`, `data.json`) лежат в рабочей папке программы. Необязательное поле `activeFile` в `lesson.json` задаёт исходник для первой вкладки редактора. В уроках Bukkit и Fabric это `Main.java` — готовый сценарий тестового runtime; класс плагина или мода остаётся в соседней вкладке. Тесты могут задавать файлы до запуска и проверять их после:

```json
{
  "name": "Конфига нет — создаётся из ресурсов",
  "files": {},
  "expectedOutput": "Привет! Мест: 20\n",
  "expectedFiles": { "config.yml": "greeting: Привет\nmax-players: 20\n" }
}
```

`files` — содержимое рабочей папки перед запуском (`{}` — пустая папка; без `files` берутся файлы из проекта ученика), `expectedFiles` — какими файлы должны стать. Если задан только `expectedFiles`, вывод не проверяется. Пример такого урока — `backend/src/test/resources/test-lessons/01-config-demo`.

Типы требований и заполнители случайных тестов описаны в `Requirement.java` и `RandomInput.java`. Вывод сравнивается без учёта `\r\n`, пробелов в конце строк и пустых строк в конце.

## Безопасность

- Каждая программа выполняется в **отдельной JVM** с лимитами времени (общего и процессорного), памяти, потоков и объёма вывода, с пустыми переменными окружения.
- Внутри дочерней JVM работает **менеджер безопасности** с почти пустой политикой: код ученика не может открывать сетевые соединения, запускать процессы и читать переменные окружения, а файлы — только в своей рабочей папке, которая создаётся заново на каждый запуск и удаляется после него. Поэтому сервер запускается только на Java 21: в Java 24+ менеджера безопасности нет, и тогда сервер откажется выполнять код (это видно в `/api/health`).
- Лаунчер песочницы — отдельный модуль, который ничего не открывает, а из модулей JDK подключается только Java SE (без `jdk.unsupported` и `sun.misc.Unsafe`). Поэтому рефлексию, без которой не работают Gson и SnakeYAML, можно разрешить: до защиты и внутренностей JDK она не дотягивается.
- Размер файлов ограничен дважды: ОС не даёт записать файл больше 2 МБ (`ulimit -f`), а сервер останавливает программу, если в папке больше 4 МБ или 100 файлов.
- Запросы ограничены по частоте и размеру, одновременные программы — по IP; ответы идут с CSP и другими заголовками безопасности.
- Код учеников не сохраняется; статистика анонимна — без cookies и IP, с учётом Do Not Track и Global Privacy Control.

Для большего запаса прочности можно дополнительно изолировать сам контейнер: `--read-only --tmpfs /tmp` (песочница пишет только во временный каталог, статистика — в том `/app/data`), `--cap-drop=ALL`, `--security-opt no-new-privileges`, `--pids-limit 512` и без доступа к внутренней сети.
